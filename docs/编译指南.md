# R528S3-DshanPi 最终版编译与烧录指南

本文只记录本提交版的可复现流程。源码仓位于 openvela 工作区的
`contest2026_113_veladuxingke/`，构建命令必须从工作区根目录执行。

## 1. 前置条件

- Ubuntu 20.04 或更高版本，已安装 openvela 编译依赖、`repo` 和 ARM 交叉编译工具链；
- 256 MiB NAND 的百问网 R528S3-DshanPi；
- 可选 ST7796U2 触摸屏、板载 DMIC/音频输出和 TWI3 环境传感器；
- 如需导出历史或采集语料，准备 FAT32 microSD 卡。

首次搭建环境可先阅读 [`board/r528s3-dshanpi/README_zh-cn.md`](../board/r528s3-dshanpi/README_zh-cn.md)。

## 2. 获取工程

```bash
mkdir openvela-workspace
cd openvela-workspace
repo init -u https://github.com/open-vela/contest2026_113_veladuxingke \
  -b dev-ai-contest-2026 -m contest2026_113_veladuxingke.xml
repo sync -c -j8
```

同步完成后，确认 `contest2026_113_veladuxingke/` 与 `nuttx/`、`apps/`、
`vendor/` 位于同一工作区层级。

如果使用的是从旧模板升级的已有工作区，先删除旧模板软链接和应用 Kconfig
缓存。它们是工作区生成文件，不属于参赛仓：

```bash
if [ -L packages/demos/contest2026_113_hello_app ]; then
  unlink packages/demos/contest2026_113_hello_app
fi
if [ -L packages/demos/contest2026_113_hello_world ]; then
  unlink packages/demos/contest2026_113_hello_world
fi
rm -f packages/demos/Kconfig packages/demos/.kconfig
```

## 3. 应用补丁

```bash
./contest2026_113_veladuxingke/tools/apply_vendor_patches.sh
```

脚本会检查 Micro-TF、DMIC、TWI3、音频、Codec、NxPlayer 和 FT5x06 依赖，
并以可重复方式应用仓内 `patches/`。若提示补丁已应用，可以直接继续；若提示
不匹配，应保留现场并检查对应公共仓库版本。

## 4. 编译

```bash
source build/envsetup.sh
./build.sh contest2026_113_veladuxingke/board/r528s3-dshanpi/configs/nsh/ -j8
```

首次构建、切换配置或 `repo sync` 后，执行一次干净构建：

```bash
./build.sh contest2026_113_veladuxingke/board/r528s3-dshanpi/configs/nsh/ -j8 distclean
./build.sh contest2026_113_veladuxingke/board/r528s3-dshanpi/configs/nsh/ -j8
```

构建应产生 `nuttx/nuttx.bin`，并在板级配置中启用 `R528_ST7796`、四个比赛
应用、音频、TFLite Micro KWS 和 Micro-TF。不要通过命令行临时注入
`CONFIG_*` 变量来绕过 Kconfig；修改配置后重新执行 `distclean`。

## 5. 主机端检查

工具测试不访问开发板，也不需要 API Key：

```bash
cd contest2026_113_veladuxingke
python3 -m unittest discover -s tools -p 'test_*.py'
git diff --check
```

若主机缺少 `numpy` 等可选依赖，请把依赖安装到仓库外的虚拟环境或临时目录，
不要把缓存、模型中间文件或个人语料写入本仓。

## 6. 打包 NAND 镜像

回到 openvela 工作区根目录：

```bash
# 先从 openvela 根目录加载通用环境，不能只 source lichee/envsetup.sh。
cd /path/to/openvela
source build/envsetup.sh

cd vendor/allwinnertech/lichee
source envsetup.sh
lunch_nuttx r528s3-dshanpi
pack
```

`lunch_nuttx` 和 `pack` 是 lichee 环境在当前 Bash 中定义的函数；不要在
`source envsetup.sh` 后再启动 `bash`，否则新 shell 不会继承这些函数。若看到
`prebuilts/kconfig-frontends` 不存在，说明通用环境没有先加载。回到工作区根目录，
重新执行上面的两次 `source`，确认 `type lunch_nuttx` 和 `type pack` 都显示为
函数后再打包。

目标文件为：

```text
vendor/allwinnertech/lichee/out/r528s3/dshanpi_nand/rtos_nuttx_r528s3-dshanpi_uart0_256Mnand.img
```

以日志同时出现以下标志、且目标文件时间为本次构建时间为准：

```text
Dragon execute image.cfg SUCCESS !
pack finish
```

某些公共资源缺失时 `pack` 可能返回非零并打印回退提示；此时必须再次核对上面
两行、镜像存在性以及 `nuttx.bin`、`nsh.fex` 和镜像的时间与 SHA-256，不能只看
进程返回码。

NAND 镜像位于工作区外层输出目录，不属于本参赛仓提交内容。源码仓只提交复现
构建所需的配置、补丁、资源、工具、文档和日志。

## 7. 烧录与首次启动

1. 在 Windows PhoenixSuit 中选择生成的 `.img`；
2. 开发板断电，按住 FEL 键，通过 USB 连接并上电；
3. 开始升级，完成后断电重启；
4. 等待桌面出现，确认无需在 NSH 中手动启动 `wifi_manager`、`lan_panel` 或
   `routine_mgr`。

需要调试时按板级配置连接调试串口，参数为 `1500000 8N1`；控制台选择和插座
以 `board/r528s3-dshanpi/configs/nsh/defconfig` 及板卡丝印为准。

## 8. 功能验收顺序

1. 确认 SHT40、BH1750 和 SGP30 状态分别进入实时或预热状态；
2. 在屏幕 Wi-Fi 页面输入 SSID/密码。取得 IPv4 后，屏幕弹出 IP、网页地址和
   四位令牌；联网时自动 NTP 校时，断网后系统时钟继续走时；
3. 浏览器输入四位令牌，检查实时值、温度阈值、三条日程、5 秒/10 秒/分钟级
   历史间隔、曲线点表和 SD 卡导出；
4. 点击“开始语音”，分别说出温度、湿度、光照和空气质量查询，确认对应播报。
   本版本使用点击触发，不启用唤醒词；
5. 断开网络后再次检查屏幕时间和离线语音，最后插入 FAT32 卡验证历史导出。

详细接线和验收记录见 `docs/` 中的屏幕、触摸、TWI3、音频和网络文档。
