# R528S3-DshanPi 快速上手与自定义语音模型

本文面向第一次拿到本作品的使用者，也说明如何为自己的说话人重新训练离线语音模型。
正常使用不需要串口；串口只用于调试、采集语料和查看日志。

## 1. 先了解语音识别边界

本作品使用板端 TFLite Micro 全 INT8 固定指令分类模型，不是通用中文 ASR。当前固件
采用已采集说话人的个人原型，其他人的声音、口音、距离或噪声环境变化较大时，可能被
判定为“无法识别”。模型只处理以下四类查询：

```text
现在温度多少
现在湿度多少
现在光照多少
现在空气质量怎么样
```

最终产品采用点击屏幕“开始语音”触发一次录音，不启用“你好 Vela”连续唤醒。每次查询
完成后都要重新点击按钮。

## 2. 硬件和镜像

需要准备：

- 百问网 R528S3-DshanPi 256 MiB NAND 版；
- ST7796U2 480×320 触摸屏、板载 DMIC 和音频输出；
- SHT40、BH1750/GY-302、SGP30，接到 TWI3；
- 可选 FAT32 microSD 卡，用于历史导出或语料采集。

传感器接线和引脚见 [`TWI3 环境传感器记录`](TWI3环境传感器开发与验收记录.md)。编译主机
建议使用 Ubuntu 20.04 或更高版本，并先安装 openvela 的依赖、`repo` 和 ARM 工具链。

## 3. 获取、编译和打包

在 openvela 工作区根目录执行：

```bash
repo init -u https://github.com/open-vela/contest2026_113_veladuxingke \
  -b dev-ai-contest-2026 -m contest2026_113_veladuxingke.xml
repo sync -c -j8

./contest2026_113_veladuxingke/tools/apply_vendor_patches.sh
source build/envsetup.sh
./build.sh contest2026_113_veladuxingke/board/r528s3-dshanpi/configs/nsh/ -j8
```

生成 NAND 镜像时，必须保持在同一个 Bash 中，按以下顺序执行：

```bash
source build/envsetup.sh
cd vendor/allwinnertech/lichee
source envsetup.sh
lunch_nuttx r528s3-dshanpi
pack
```

不要在 `source envsetup.sh` 后再输入 `bash`，否则 `lunch_nuttx` 和 `pack` 函数不会被
子 shell 继承。镜像路径为：

```text
vendor/allwinnertech/lichee/out/r528s3/dshanpi_nand/rtos_nuttx_r528s3-dshanpi_uart0_256Mnand.img
```

详细的依赖、补丁和打包说明见 [`编译指南`](编译指南.md)。

## 4. 烧录和第一次启动

1. 在 Windows PhoenixSuit 中选择上面的 `.img`。
2. 开发板断电，按住 FEL 键，通过 USB 连接并上电。
3. 等待烧录完成，断电后重新上电。
4. 等待桌面出现。`wifi_manager`、`lan_panel` 和 `routine_mgr` 已配置为开机自启动，
   不需要在 NSH 中手动输入启动命令。

串口调试参数为 `1500000 8N1`。如果只想使用产品功能，可以不连接串口。

## 5. Wi-Fi、网页和语音验收

1. 等待 SHT40、BH1750 进入实时状态；SGP30 上电后需要短暂预热。
2. 在屏幕 Wi-Fi 页面扫描并选择 SSID，输入密码后点击连接。
3. 联网成功后，屏幕弹窗显示 IP、网页地址和 4 位令牌。电脑或手机连接同一局域网，
   打开 `http://<IP>:8080/` 并输入令牌。
4. Wi-Fi 成功后会通过 NTP 校时；之后即使断网，已校准的系统时钟仍会继续走时。
5. 在网页中可查看实时环境数据、修改高低温阈值、编辑日程、调整历史间隔、查看曲线
   数据点和导出 SD 卡历史。
6. 点击屏幕“开始语音”，在录音窗口内清晰说出一个固定指令，等待播报；下一次查询前
   再点击一次。

首次测试建议距离 DMIC 约 20--50 cm，在安静环境中以正常音量完整说完一句话。若只有
某一位说话人能稳定识别，这是当前个人模型的已知限制，不代表传感器或网页故障。

## 6. 为自己的声音训练模型

### 6.1 固定模型接口

当前固件只接受仓库训练工具生成并通过验收的七分类模型，类别顺序不能改变：

| 索引 | 类别 |
|---:|---|
| 0 | `background` |
| 1 | `unknown_speech` |
| 2 | `query_humidity` |
| 3 | `query_light` |
| 4 | `query_air_quality` |
| 5 | `query_temperature` |
| 6 | `wake_nihao_vela`（保留类别，当前产品流程不启用唤醒） |

输入必须是与板端相同的 178×40×1 固定点特征，模型输入和输出必须为 INT8，输入
量化必须是 `scale=1`、`zero_point=0`，模型文件不超过 256 KiB。不能使用任意类别名、
浮点模型或通用 ASR 模型直接替换。

### 6.2 在板上采集自己的语料

插入 FAT32 microSD，等待它挂载到 `/sdcard`，然后在 NSH 使用短的单行命令。命令中的
`-p` 是说话人 ID，`-s` 是采集会话 ID，建议只使用 ASCII 字母、数字、`_` 或 `-`：

```text
routine_mgr -K -l query_temperature -p me01 -s take_a -n 20
routine_mgr -K -l query_humidity -p me01 -s take_a -n 20
routine_mgr -K -l query_light -p me01 -s take_a -n 20
routine_mgr -K -l query_air_quality -p me01 -s take_a -n 20
routine_mgr -K -l unknown_speech -p me01 -s take_a -n 20
routine_mgr -K -l background -p me01 -s take_a -n 20
routine_mgr -K -l wake_nihao_vela -p me01 -s take_a -n 20
```

目标类别中分别说对应查询句；`unknown_speech` 说与四类查询无关的句子；`background`
保持安静并保留真实房间背景；`wake_nihao_vela` 说“你好 Vela”。为了提高对不同人的
鲁棒性，可使用多个 `speaker_id` 和多个 `session_id` 重复采集。每类至少需要 3 条才能
覆盖训练、验证和测试划分，实际建议每类 20--50 条以上。

每条录音会先写入临时文件并回放试听，确认后才发布为成对的 `.pcm` 和 `.json`。采集
结束后执行 `sync`，再取出 SD 卡；不要在录音、回放或保存过程中拔卡。

### 6.3 在主机导入和训练

把 SD 卡中某个或多个会话目录里的所有 `.pcm` 和 `.json` 直接复制到主机上的临时目录
（不要再保留会话子目录），不要把个人语料写入 Git 仓库。例如：

```bash
mkdir -p /tmp/my-kws-staging
# 将 SD 卡中的 .pcm/.json 复制到 /tmp/my-kws-staging

cd /path/to/openvela
python3 contest2026_113_veladuxingke/tools/import_kws_corpus.py \
  /tmp/my-kws-staging --output /tmp/my-kws-corpus

python3 contest2026_113_veladuxingke/tools/prepare_kws_training_data.py \
  /tmp/my-kws-corpus --output /tmp/my-kws-corpus/training
```

导入器会检查文件配对、16 kHz/16-bit/mono PCM、时长、ID、哈希和声学质量，并生成
WAV、`manifest.jsonl` 和确定性的训练划分。每个训练划分必须包含上表七个类别；带有
质量警告的样本会被训练清单排除。

主机训练需要 `numpy` 和 TensorFlow。依赖安装到仓库外的临时虚拟环境：

```bash
python3 -m venv /tmp/r528-kws-venv
/tmp/r528-kws-venv/bin/pip install numpy tensorflow-cpu==2.15.1
mkdir -p /tmp/r528-kws-site

cd /path/to/openvela
python3 contest2026_113_veladuxingke/tools/build_kws_microfrontend.py \
  /tmp/r528-kws-site/libkws_frontend.so

/tmp/r528-kws-venv/bin/python \
  contest2026_113_veladuxingke/tools/train_kws_model.py \
  /tmp/my-kws-corpus \
  --frontend-library /tmp/r528-kws-site/libkws_frontend.so \
  --output /tmp/my-kws-corpus/training/model \
  --epochs 120
```

训练命令必须输出 `accepted: true`，并在模型目录生成 `MODEL_ACCEPTED.json`。如果
模型被拒绝，先按 `evaluation.json` 中的 `rejection_reasons` 增加或清理语料，不要把
未验收模型写入固件。

### 6.4 将验收模型编译进固件

生成脚本会再次校验模型哈希、验收标记、类别顺序、阈值和 INT8 接口。先备份当前模型
数组，再生成新文件：

```bash
cd /path/to/openvela
cp contest2026_113_veladuxingke/app/routine_manager/kws_model_data.h \
  /tmp/kws_model_data.h.original
cp contest2026_113_veladuxingke/app/routine_manager/kws_model_data.cc \
  /tmp/kws_model_data.cc.original

python3 contest2026_113_veladuxingke/tools/generate_kws_model_data.py \
  /tmp/my-kws-corpus/training/model \
  --header contest2026_113_veladuxingke/app/routine_manager/kws_model_data.h \
  --source contest2026_113_veladuxingke/app/routine_manager/kws_model_data.cc
```

`kws_model_data.h/.cc` 是生成文件，不要手工改数组或阈值。随后重新应用补丁、编译、
打包并烧录，步骤与本文第 3、4 节相同。新固件启动后，逐条测试四类查询和多次连续
点击；模型数据已编译进 NuttX，不能把 `.tflite` 直接复制到 SD 卡后在运行时加载。

## 7. 失败恢复和隐私

- 新模型训练未通过时，不要执行生成步骤；原固件不会被改变。
- 已生成但测试不满意时，恢复备份并重新编译、烧录：

  ```bash
  cd /path/to/openvela
  cp /tmp/kws_model_data.h.original \
    contest2026_113_veladuxingke/app/routine_manager/kws_model_data.h
  cp /tmp/kws_model_data.cc.original \
    contest2026_113_veladuxingke/app/routine_manager/kws_model_data.cc
  ```

- 个人录音、`model_float.keras`、`evaluation.json` 和 API key 均放在仓库外；不要提交
  到 Git，也不要把 API key 写入固件、日志或网页。
- 主机端测试可在仓库目录执行：

  ```bash
  cd /path/to/openvela/contest2026_113_veladuxingke
  python3 -m unittest discover -s tools -p 'test_*.py'
  ```

更多音频状态、语料格式和验收背景见 [`中文离线语音识别开发与验收记录`](中文离线语音识别开发与验收记录.md)。
