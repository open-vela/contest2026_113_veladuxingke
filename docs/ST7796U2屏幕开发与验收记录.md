> 更新时间：2026-08-09  
> 软件状态：已按实物板卡引脚表修正全部 LCD 控制信号，待重新构建和烧录  
> 真机状态：硬件 SPI1 黄金复现镜像已点亮；颜色正确，正在依据四角色块完成 480×320 最终方向

## 1. 根因修正

新增的屏幕手册确认实体面板控制器是 **ST7796U2**，原生分辨率为 320×480，使用 4 线 SPI。旧固件按 ILI9341 240×320 和 DISP2 CPU 并行接口配置；原理图却只连接 SPI、DC、RESET 和背光。因此旧 `/dev/fb0` 测试成功只证明 RAM/G2D 软件路径执行，像素没有正确的物理通路到达这块 SPI 屏。

当前通路改为：

```text
应用 / LVGL
    → /dev/fb0 (480×320 RGB565)
    → NuttX lcd_framebuffer
    → 比赛板 r528_st7796 lower-half
    → GPIO 软件 SPI
    → ST7796U2 GRAM
```

不再使用 DISP2、ILI9341、vendor DSI `st7796s.c` 或 G2D 旋转。

## 2. 资料确认的接口要求

- 4 线 SPI：`IM[2:0]=111`（由屏幕模组硬件决定）。
- SPI Mode 0，SCK 空闲低，数据在上升沿采样，MSB first。
- RESET 低脉冲至少 10 µs；驱动使用 20 ms。
- RESET 释放后等待 120 ms，再发送命令。
- `SLPOUT (0x11)` 后等待至少 120 ms。
- `COLMOD (0x3a)=0x55`，控制接口和 RGB 接口均为 16 bit/pixel。
- 窗口：`CASET (0x2a)`、`RASET (0x2b)`、`RAMWR (0x2c)`。
- framebuffer 内的 RGB565 是小端，SPI 像素流高字节先发：红 `f8 00`、绿 `07 e0`、蓝 `00 1f`。

## 3. 实物板卡引脚与黑屏根因

用户根据实际板卡/模组引脚资料提供了最终映射。该映射与 `/home/gfc/桌面/移植备用` 中已工作过的 R528 SPI LCD 控制脚完全一致：

| 信号 | GPIO | 说明 |
|---|---:|---|
| CS | PD10 | SPI1_CS |
| SCK | PD11 | SPI1_SCK |
| MOSI | PD12 | SPI1_MOSI，屏幕数据输入 |
| MISO | PD13 | SPI1_MISO，当前只写驱动不使用 |
| DC/RS | PD14 | 命令/数据选择 |
| RESET | PD15 | 低有效复位 |
| BL/PWM | PD16 | 当前作为高电平开启的 GPIO 背光 |

触摸屏另使用 PE13=RPI_SDA、PE12=RPI_SCL、PE0=CTP_RST、PE1=CTP_INT，与 LCD 色块输出无关。

前一版依据原理图交叉网络推断成 CS=PD11、SCK=PD13、MOSI=PD14、DC=PD15、RESET=PD16、BL=PD17；烧录后 framebuffer metadata 和全部软件更新仍正常，但实体屏继续黑，证明该推断不适用于手上这块实际 PCB/模组。现在以用户提供的实物引脚为最高优先级证据，全部改为 PD10/PD11/PD12/PD14/PD15/PD16。

本轮仍先使用 GPIO 软件 SPI，以只改变引脚映射；实物 SPI 信号正好落在原生 SPI1 组上，屏幕点亮并稳定后可另行评估硬件 SPI 性能迁移。

## 7. 无额外仪器的真机验证顺序

1. 烧录修正后的新镜像并完整断电重启。串口必须看到：

```text
st7796: softspi CS=PD10 SCK=PD11 MOSI=PD12 DC=PD14 RESET=PD15 BL=PD16; PD13=MISO unused
```

若仍显示 CS=PD11、SCK=PD13 或 BL=PD17，说明运行的是旧镜像或旧生成配置，此次屏幕结果无效。

2. 运行：

```text
nsh> ls /dev
nsh> fb /dev/fb0
nsh> st7796_test --cycles 3
```

3. 期望 metadata：480×320、RGB565、16 bpp、stride 960、fblen 307200。
4. 肉眼确认黑、白、红、绿、蓝、四色象限和四角：左上红、右上绿、左下蓝、右下白，并观察局部更新色块。
5. `FBIO_UPDATE ret=0` 仅表示软件和 GPIO 写循环完成，不是面板 ACK；必须以肉眼图案为准。
6. 能显示但方向错误时，只调 MADCTL 的 MX/MY/MV；红蓝互换时只调 BGR，不使用 G2D 掩盖。
7. 色块正确后运行 `st7796_test --cycles 100`，再运行 `routine_mgr --ascii --duration 30`。
8. 若实物引脚日志正确但仍黑，再检查 FPC 接触、面板接口模式绑带以及控制器/初始化序列；备用目录可继续作为工作时序参考，但不要在同一轮同时更换引脚、控制器序列和总线实现。

有条件取得仪器后，可附加验证红屏时的 Mode 0 波形：

```text
2a 00 00 01 df
2b 00 00 01 3f
2c f8 00 f8 00 ...
```
