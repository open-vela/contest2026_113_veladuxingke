# 局域网面板与历史数据指南

本指南对应当前提交版的 `wifi_manager`、`lan_panel` 和
`routine_manager`。面板只面向同一局域网内的单用户管理，不提供公网服务或
HTTPS。

## 1. 开机与联网

板级 `rcS` 在 `/data` 可用后自动启动三个服务：

```text
wifi_manager &
lan_panel &
routine_mgr &
```

因此不需要在 NSH 中手动启动。`lan_panel` 默认监听 TCP `8080`，在没有
IPv4 时也会先启动并等待网络；`routine_mgr` 和传感器页面可以离线工作。

屏幕 Wi-Fi 页面可以扫描 SSID、输入密码并提交配置。提交后页面保持在当前
页面，`wifi_manager` 会自动关联、获取 DHCP 地址并按周期重试失败连接。取得
IPv4 后，屏幕弹窗显示 SSID、IP、网页地址和四位数字令牌。

联网成功后 `wifi_manager` 通过 NTP 校准系统时间；断网后使用已经校准的系统
时钟继续走时，重新联网时会再次校准。没有有效时间时，历史记录不会伪造日期。

## 2. 四位访问令牌

首次启动时 `lan_panel` 从 `/dev/urandom` 生成恰好四位十进制令牌，保存为：

```text
/data/panel.auth
```

文件权限为 `0600`。升级时检测到旧格式的长令牌会重新生成四位令牌。令牌不会
写入 Wi-Fi 状态、历史记录或启动日志；独立使用时以屏幕联网成功弹窗为准，
不依赖串口。重新进入屏幕 Wi-Fi 页面也可以再次查看连接信息。

浏览器首次打开页面会提示输入令牌，并把令牌暂存于当前标签页的
`sessionStorage`。除根页面外的接口均使用：

```text
Authorization: Bearer <4位令牌>
```

Wi-Fi 密码只用于写入 `/data/wifi.cfg`，状态接口和页面不会回显已保存密码。

## 3. 页面功能

### 实时状态

页面定时刷新当前温度、湿度、光照、eCO₂、TVOC、传感器状态、当前日期时间和
下一条日程。状态卡会区分实时、预热、过期和离线，不会把旧值伪装成实时值。

### 温度阈值与日程

在“日程与告警”区域可以设置低温和高温阈值，并编辑三条今日日程。每条日程
包含 `HH:MM` 时间和一段 UTF-8 文字；保存后设备会原子更新配置，当前日期到点
时在屏幕提示并播报当前时分秒和日程文字。配置会保存在：

```text
/data/routine/config.json
```

### 运行曲线与采样间隔

“运行曲线”弹窗打开时会从设备重新读取历史，不使用上次页面缓存。每个点都
显示日期、时间、温度、湿度、光照、eCO₂、TVOC 和传感器状态；曲线图同时提供
点对应的数值表，便于读取精确数据。

可选记录间隔为：

```text
5 秒、10 秒、1 分钟、5 分钟、10 分钟、30 分钟、60 分钟
```

默认间隔为 1 分钟。间隔改变后由 `routine_mgr` 按新的时间槽追加记录；历史文件
位于：

```text
/data/routine/history.jsonl
```

点击“加载全部历史”同样会发起新的请求，并显示本次加载的记录数及起止日期，
而不是显示内部事件日志。

### SD 卡导出

在运行曲线弹窗中确认“导出到 SD 卡”后，面板调用导出接口。设备会自动尝试把
FAT32 microSD（`/dev/mmcsd1`）挂载到 `/sdcard`，并在以下目录创建不覆盖旧文件
的 JSONL 副本：

```text
/sdcard/routine_history/routine-history-<epoch>.jsonl
```

导出完成后页面显示实际路径；未插卡、没有历史或文件系统错误会显示明确错误，
不会重试可能造成重复文件的导出请求。

## 4. HTTP 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/v1/status` | 当前环境、时间、阈值和日程快照 |
| `GET` | `/api/v1/wifi/status` | 脱敏 Wi-Fi 关联、DHCP 和重试状态 |
| `POST` | `/api/v1/wifi/config` | 写入 bounded SSID/密码配置并触发重连 |
| `GET` | `/api/v1/routine/config` | 读取阈值、三条日程和记录间隔 |
| `POST` | `/api/v1/routine/config` | 原子保存上述配置 |
| `GET` | `/api/v1/history` | 重新读取全部环境历史 JSONL |
| `POST` | `/api/v1/history/export` | 导出历史到 FAT32 SD 卡 |
| `POST` | `/api/v1/light/config` | 保存智能照明阈值和档位 |

示例（把占位符替换为屏幕显示值）：

```bash
TOKEN="1234"
IP="192.0.2.10"
curl --fail --no-buffer \
  -H "Authorization: Bearer $TOKEN" \
  "http://$IP:8080/api/v1/status"
curl --fail --no-buffer \
  -H "Authorization: Bearer $TOKEN" \
  "http://$IP:8080/api/v1/history"
```

服务只接受实现过的 `GET`、`HEAD` 和 `POST`，不提供文件浏览、上传、删除、重命名
或命令执行；路径参数会拒绝路径穿越和隐藏临时文件。

## 5. 浏览器请求失败处理

页面对读取状态、读取配置和保存配置的短暂网络断开执行有界重试，并在请求中
使用 `cache: no-store`；导出请求不自动重试，避免生成重复文件。令牌失效时会
清除当前标签页令牌并要求重新输入。

如果浏览器提示 `NetworkError` 或 `Failed to fetch`：

1. 确认电脑和开发板仍在同一局域网，且弹窗中的 IP 未变化；
2. 重新打开 `http://<IP>:8080/`，输入屏幕显示的四位令牌；
3. 确认屏幕 Wi-Fi 状态为已取得 IPv4；
4. 烧录新固件后仍显示旧页面时，使用无痕窗口或清理该 IP 的缓存。

## 6. 设备文件

```text
/data/wifi.cfg             Wi-Fi 配置（密码，0600）
/data/wifi.status          脱敏连接状态
/data/panel.auth           四位网页令牌（0600）
/data/routine/config.json  阈值、日程、记录间隔
/data/routine/status.json  当前状态快照
/data/routine/history.jsonl  环境历史
/data/routine/events.log   设备诊断事件（网页历史页不展示）
```

以上接口和页面均只在局域网内使用。不要把 `8080` 端口直接暴露到互联网。
