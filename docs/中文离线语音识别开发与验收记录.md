# 中文离线语音识别开发与验收记录

## 1. 最终产品边界

`routine_mgr` 在 R528 上从板载 DMIC 录制 16 kHz、16-bit、单声道 PCM，使用
全 INT8 TFLite Micro 模型在本地完成固定指令分类，再由本地 PCM 片段拼接中文
播报。点击屏幕“开始语音”启动一次录音；每次查询完成后资源释放，可以连续
点击进行下一次查询。

最终产品支持四类指令：

```text
现在温度多少
现在湿度多少
现在光照多少
现在空气质量怎么样
```

四类指令分别读取 SHT40 温度/湿度、BH1750 光照和 SGP30 eCO₂/TVOC，并使用
对应播报资源。高、低温阈值由网页配置；越界时自动播报“温度过低注意保暖”或
“温度过高注意高温”对应的中文提示。

模型输出还保留 `wake_nihao_vela` 类，便于语料和误触发评估；本提交版不启用
唤醒词，唤醒类别不会进入正常查询路由。模型是已采集说话人的个人原型，不是
通用中文 ASR，也不依赖云端服务。

## 2. 模型与前端

模型契约由 [`app/routine_manager/kws_model_data.h`](../app/routine_manager/kws_model_data.h)
固定：

| 项目 | 值 |
|---|---|
| 输出类别 | 7（背景、未知、湿度、光照、空气质量、温度、唤醒） |
| 输入特征 | 178 帧 × 40 通道，INT8，scale=1，zero point=0 |
| 模型大小 | 65,480 bytes |
| 推理引擎 | TFLite Micro，Conv2D/AveragePool2D/Reshape/FullyConnected/Softmax |

录音先做有符号 DC 去除和 VAD 起始搜索，再对齐到固定窗口，避免说话起始时刻
改变而导致同一句话只能偶尔命中。预测必须同时满足 argmax 和该类别阈值；未
满足时返回未知，不播报错误数据。

## 3. 播报资源

板端资源位于 `/etc/routine_voice`，仓内母版和处理清单位于
`source_assets/routine_voice/`。`tools/prepare_voice_assets.py` 检查 WAV 格式、
采样率、声道、峰值和哈希，并生成 16 kHz 双声道 PCM。温度、湿度、光照、eCO₂、
TVOC、数字、单位、日程和高低温提示均使用固定片段拼接。

MiMo TTS/ASR 只用于用户明确选择的主机侧语音资源生成或转写基线：API Key 通过
隐藏输入读取，暂存于用户私有目录，用后删除，不写入仓库、固件、日志或清单。

## 4. 语料采集（可选）

启用 `CONFIG_ROUTINE_MANAGER_KWS_CAPTURE` 后，可在有 FAT32 microSD 的板上
采集训练语料。当前 NSH 行宽有限，使用单行短命令，例如：

```text
routine_mgr -K -l query_temperature -p s001 -s smoke_a -n 1
```

正式样本写入 `/sdcard/kws_corpus/<session>/`，成对保存 `.pcm` 和 `.json`；
程序先写临时文件，确认试听后再原子发布，不覆盖已有 take。取卡后在主机运行：

```bash
python3 tools/import_kws_corpus.py <staging-dir> --output <corpus-dir>
```

导入器会检查配对、格式、时长、ID、哈希和声学指标。真实录音和 MiMo 响应应放在
仓库外，不随源码提交。

## 5. 验收清单

- `routine_mgr --selftest` 通过模型、路由和播报格式契约；
- 主机工具测试覆盖前端、模型数据、语料导入、播报资源和连续音频生命周期；
- 真机上分别测试四类查询、取消操作、传感器预热/离线状态和高低温告警；
- 连续点击多次后，录音线程、播放器和临时 PCM 均能释放，下一次查询仍可开始；
- 关闭 Wi-Fi 后，四类查询仍在本地运行；
- 唤醒词类别保持禁用，不能把模型中的 wake 类误写成产品功能。

模型和前端源码分别见 `voice_recognizer_kws.cc`、`kws_frontend.cc` 和
`kws_model_data.h`；语音状态机见 `audio_service.c`，传感器播报格式见
`voice_reply.c`。
