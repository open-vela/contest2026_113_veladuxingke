# FT5x06 / FT6336 触摸开发与验收记录

> 更新时间：2026-08-10；真机验收通过（含 180° 坐标修复）

## 1. 软件架构

触摸 IC 使用 NuttX 通用驱动：

```text
nuttx/drivers/input/ft5x06.c
```

它注册 `/dev/input0`，提供：

- `read`：读取 `touch_sample_s` 的 DOWN/MOVE/UP；
- `ioctl`：设置/读取 I2C 频率，并补充 `TSIOC_GETMAXPOINTS`；
- `poll`：等待触摸事件。

板级代码位于：

```text
board/r528s3-dshanpi/src/r528_ft5x06.c
```

板级代码负责复位、GPIO 中断、坐标旋转和调用 `ft5x06_register()`。

## 2. 实物引脚

| 信号 | GPIO | 功能 |
|---|---:|---|
| RPI_SCL | PE12 | TWI2 SCL，mux 2 |
| RPI_SDA | PE13 | TWI2 SDA，mux 2 |
| CTP_RST | PE0 | 低有效复位 |
| CTP_INT | PE1 | falling-edge 中断 |

配置：

```text
I2C bus: TWI2 (/dev/i2c2)
7-bit address: 0x38
frequency: 400 kHz
device node: /dev/input0
mode: single point
```

PE0 先保持低电平 10 ms，再释放并等待 300 ms。PE1 使用上拉和下降沿中断。

## 3. 横屏坐标

最终屏幕为 480×320，LCD MADCTL 为 0xE8。2026-08-09 的独立 `tc` 验收曾认为初始映射方向正确：

```text
screen_x = raw_y
screen_y = 319 - raw_x
```

但 2026-08-10 在完整 LVGL 界面上复测发现：实体右下角“语音：演示”区域被报告为 `(0,0)`，实体左上角“桌面管家”区域被报告为约 `(479,319)`。这说明最终 LVGL 坐标的 X、Y 均相反，即相对画面旋转 180°，不是简单交换轴。

板级修复改为：

```text
screen_x = 479 - raw_y
screen_y = raw_x
```

该公式等价于在原最终坐标基础上执行：

```text
fixed_x = 479 - old_x
fixed_y = 319 - old_y
```

驱动把结果夹到：

```text
x = 0..479
y = 0..319
```

如果实体触摸层的贴合方向与假设不同，只修改板级 `r528_ft5x06_transform()`，不在 LVGL 或通用 FT5x06 驱动中硬编码 R528 方向。

## 4. LVGL 接入

`routine_manager` 使用：

```text
framebuffer: /dev/fb0
input:       /dev/input0
```

LVGL 启动时会调用 `TSIOC_GETMAXPOINTS`；单点驱动返回 1。成功读取的长度必须为 `SIZEOF_TOUCH_SAMPLE_S(1)`。

### 5.1 事件 flags 对照

`tc` 打印十六进制 `flags`，不会直接显示事件名称：

| flags | 事件 |
|---:|---|
| `0x19` | DOWN：新触摸，ID 和坐标有效 |
| `0x1a` | MOVE：移动，ID 和坐标有效 |
| `0x0c` | UP：抬起，ID 有效 |

- [x] 系统可进入 NSH，不再在 `AppBringUp` 中崩溃；

- [x] 日程取消、延后 10 分钟、完成状态和“下一项”推进均正常；
- [x] 顶部状态总览及 SHT40/BH1750/SGP30 详情弹框触摸操作正常。

启动崩溃的根因是通用 `ft5x06_register()` 在 `attach()` 前调用 `enable(false)`，而旧板级实现直到 `attach()` 中才解析 `g_ft5x06_irq`，导致 IRQ 0 进入 R528 GPIO HAL。当前实现已在调用通用注册函数前通过 `hal_gpio_to_irq()` 解析 PE1 IRQ，并在中断请求失败时清理保存的 ISR 状态。

必要时读取识别寄存器：

```text
nsh> i2c get -b 2 -a 38 -f 400000 -r a3
nsh> i2c get -b 2 -a 38 -f 400000 -r a6
nsh> i2c get -b 2 -a 38 -f 400000 -r a8
```
